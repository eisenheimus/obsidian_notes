
#### Структура каталогов
```
ansible-project/
├── ansible.cfg              # Главный файл конфигурации (как на вашем скриншоте)
├── inventory/               # Каталог с описанием серверов (хостов)
│   ├── production           # Инвентарь для продакшена (INI или YAML формат)
│   ├── staging              # Инвентарь для тестового окружения
│   └── group_vars/          # Переменные для групп хостов
│       ├── all.yml          # Переменные для ВСЕХ хостов
│       ├── webservers.yml   # Переменные только для группы webservers
│       └── dbservers.yml    # Переменные только для группы dbservers
├── playbooks/               # Ваши сценарии (плейбуки)
│   ├── site.yml             # Главный плейбук (запускает всё)
│   ├── webservers.yml       # Плейбук для настройки веб-серверов
│   └── dbservers.yml        # Плейбук для настройки БД
├── roles/                   # Каталог с ролями (переиспользуемая логика)
│   ├── common/              # Роль "базовая настройка" (для всех серверов)
│   │   ├── tasks/
│   │   │   └── main.yml     # Список задач
│   │   ├── handlers/
│   │   │   └── main.yml     # Обработчики (например, перезапуск службы)
│   │   ├── templates/
│   │   │   └── ntp.conf.j2  # Шаблоны Jinja2
│   │   ├── files/
│   │   │   └── script.sh    # Статические файлы для копирования
│   │   ├── vars/
│   │   │   └── main.yml     # Переменные роли (высокий приоритет)
│   │   ├── defaults/
│   │   │   └── main.yml     # Переменные роли по умолчанию (низкий приоритет)
│   │   └── meta/
│   │       └── main.yml     # Зависимости роли от других ролей
│   └── nginx/               # Роль для установки Nginx
│       └── ... (та же структура)
├── group_vars/              # (Альтернатива) Переменные на уровне всего проекта
├── host_vars/               # Переменные для конкретных хостов
│   └── web1.example.com.yml
└── filter_plugins/          # Ваши кастомные фильтры для Jinja2 (Python)
```


#### Упрощенная структура (для маленьких проектов)

Если проект маленький, не обязательно создавать все эти папки. Часто делают так:

```
my-project/
├── ansible.cfg
├── hosts.ini          # Инвентарь прямо в корне
├── site.yml           # Один большой плейбук
└── templates/         # Шаблоны рядом с плейбуком
```


### 1. `inventory/` (Инвентарь)

Здесь описывается, **какие серверы** существуют и **как они сгруппированы**.

- **Формат:** Может быть INI (простой текст) или YAML.    
- **Пример INI (`inventory/production`):**

    ```ini
    [webservers]
    web1.example.com
    web2.example.com
    
    [dbservers]
    db1.example.com
    
    [all:vars]
    ansible_user=admin
    ```

- **Зачем делить на файлы:** Чтобы отделить продакшен от теста. Вы запускаете `ansible-playbook -i inventory/production playbooks/site.yml`, и Ansible берет сервера только из этого файла.


### 2. `group_vars/` и `host_vars/` (Переменные)

Это самое важное место для хранения настроек (пароли, порты, версии ПО).

- **`group_vars/all.yml`**: Переменные, которые применяются ко **всем** серверам (например, `ntp_server: pool.ntp.org`).

- **`group_vars/webservers.yml`**: Переменные только для группы `webservers` (например, `http_port: 80`).

- **`host_vars/web1.example.com.yml`**: Переменные для **конкретного** сервера (например, уникальный IP или специфичный сертификат).

- _Правило приоритета:_ Переменные хоста переопределяют переменные группы, а переменные группы — общие переменные.


### 3. `playbooks/` (Плейбуки)

Это сценарии, которые описывают, **что делать**.

- **`site.yml`**: Это "мастер-плейбук". Обычно он выглядит так:
- 
```yaml 
    - hosts: all
      roles:
        - common
    - hosts: webservers
      roles:
        - nginx
    - hosts: dbservers
      roles:
        - postgresql
```
    
    

    
    Запустив один этот файл, вы настроите всю инфраструктуру.
    

### 4. `roles/` (Роли) — Сердце Ansible

Роль — это способ упаковать задачи, переменные и файлы в переиспользуемый блок. Вместо того чтобы писать 100 строк в плейбуке, вы пишете `roles: - nginx`.

Структура внутри роли (папка `roles/nginx/`):

- **`tasks/main.yml`**: Основной список действий (установить пакет, скопировать конфиг, запустить сервис).
    
- **`handlers/main.yml`**: Действия, которые вызываются только при изменении (например, `restart nginx`). Они срабатывают в конце плейбука.
    
- **`templates/`**: Файлы конфигураций с расширением `.j2` (Jinja2). В них можно подставлять переменные (например, `listen {{ http_port }};`).
    
- **`files/`**: Статические файлы, которые не нужно менять (скрипты, картинки), просто копируются на сервер.
    
- **`defaults/main.yml`**: Переменные роли с самым низким приоритетом. Их легко переопределить снаружи. Здесь хранят настройки "по умолчанию".
    
- **`vars/main.yml`**: Переменные с высоким приоритетом. Их сложно переопределить. Используются для внутренних нужд роли, которые не должны меняться.
    
- **`meta/main.yml`**: Здесь указываются зависимости. Например, роль `nginx` может зависеть от роли `common` (чтобы сначала настроить базовую систему).
    

### 5. `ansible.cfg`

Это файл настроек самого движка Ansible (тот, что на вашем скриншоте). Он лежит в корне проекта. Ansible ищет его в текущей директории в первую очередь.

### Секция `[defaults]` (Основные настройки)

1. **`host_key_checking = false`**
    
    - **Что делает:** Отключает проверку SSH-ключей удаленных хостов.
        
    - **Зачем нужно:** Когда вы подключаетесь к новому серверу по SSH, он спрашивает: "Вы уверены, что хотите продолжить подключение (yes/no)?". Ansible — автоматизированный инструмент, он не может вводить "yes" вручную. Эта настройка говорит ему: "Не спрашивай, просто подключайся". Это удобно в тестовых средах, но снижает безопасность (риск MITM-атак).
        
2. **`fact_caching = jsonfile`**
    
    - **Что делает:** Указывает, _как_ Ansible будет кэшировать собранные факты (информацию о системе: IP, версия ОС, память и т.д.).
        
    - **Значение `jsonfile`:** Сохранять эти данные в виде JSON-файлов на локальной машине (где запущен Ansible).
        
3. **`fact_caching_connection = /tmp/facts_cache`**
    
    - **Что делает:** Указывает _куда_ сохранять кэш фактов.
        
    - **Значение:** В папку `/tmp/facts_cache`. Это позволяет не собирать факты заново при каждом запуске плейбука, что ускоряет работу.
        
4. **`library = library`**
    
    - **Что делает:** Указывает путь к папке с пользовательскими (custom) модулями Ansible.
        
    - **Значение:** Если вы напишете свой модуль на Python и положите его в папку `library` рядом с плейбуком, Ansible сможет его использовать.
        
5. **`gather_facts = true`**
    
    - **Что делает:** Разрешает автоматический сбор фактов (информации) о целевых хостах перед выполнением задач.
        
    - **Значение `true`:** Ansible по умолчанию будет запускать модуль `setup`, чтобы узнать состояние сервера.
        
6. **`interpreter_python = auto`**
    
    - **Что делает:** Указывает, какой интерпретатор Python использовать на удаленной машине.
        
    - **Значение `auto`:** Ansible сам попытается найти установленный Python (python3, python2 и т.д.). Это важно, так как современные системы часто не имеют `python` в PATH, только `python3`.

### 6. `filter_plugins/`

Если вам не хватает стандартных фильтров Jinja2 (например, для сложной обработки строк), вы можете написать свой фильтр на Python и положить его сюда.
