##### Популярные Ad-hoc команды (одноразовые)


1. Проверка связи (самое первое, что делают):
```bash
ansible all -i inventory/production.ini -m ping
Проверит все хосты из инвентаря.
```
  
2. Выполнение shell-команд на серверах:
```bash
ansible webservers -i inventory/production.ini -m shell -a "uptime"
ansible all -i inventory/production.ini -m command -a "df -h"

# -a — аргументы, передаваемые модулю.
```

***Важно: command безопаснее (не использует шелл), shell нужен, если используются пайпы |, редиректы > или переменные окружения.

3. Управление пакетами (apt/yum):
```bash
ansible webservers -m apt -a "name=nginx state=present" --become
ansible dbservers -m yum -a "name=postgresql state=latest" --become

# --become (или -b) — выполнить от имени root (sudo).
```
state=present — установить, если нет. state=absent — удалить. state=latest — обновить до последней версии.

4. Управление сервисами:
```bash
ansible webservers -m service -a "name=nginx state=restarted" --become
ansible webservers -m service -a "name=nginx enabled=yes" --become

# state=restarted — перезапустить.
# nabled=yes — добавить в автозагрузку.
```
  
5. Копирование файлов:
```bash
ansible webservers -m copy -a "src=/local/file.conf dest=/etc/nginx/nginx.conf mode=0644" --become

# Копирует файл с локальной машины на удаленную.
```
  
6. Сбор фактов (информации о сервере):
```bash
ansible web1.example.com -m setup
ansible web1.example.com -m setup -a "filter=ansible_eth*"
#Выведет огромный JSON со всей информацией о системе. Фильтр помогает оставить только нужное (например, сетевые интерфейсы).
```
  
7. Создание пользователей:
```bash
ansible all -m user -a "name=deploy shell=/bin/bash groups=sudo" --become
```


##### Популярные команды ansible-playbook (запуск плейбуков)

  1. Обычный запуск*
```bash
ansible-playbook -i inventory/production.ini playbooks/site.yml
```

2. Проверка синтаксиса (dry-run):
```bash
ansible-playbook -i inventory/production.ini playbooks/site.yml --syntax-check
ansible-playbook -i inventory/production.ini playbooks/site.yml --check

# --syntax-check — проверит YAML на ошибки.
# --check — покажет, что было бы сделано, но не будет ничего менять. Идеально для теста перед продакшеном.
```
  
3. Запуск с указанием конкретных хостов (лимит):
```bash
ansible-playbook -i inventory/production.ini playbooks/site.yml --limit web1.example.com

ansible-playbook -i inventory/production.ini playbooks/site.yml --limit webservers
```

4. Запуск с тегами (только часть задач):
```bash
ansible-playbook -i inventory/production.ini playbooks/site.yml --tags "nginx,ssl"
ansible-playbook -i inventory/production.ini playbooks/site.yml --skip-tags "debug"

# В плейбуке задачи можно помечать тегами (tags: nginx). Это позволяет запускать только нужные куски.
```
  
5. Подробный вывод (для отладки):
```bash
ansible-playbook -i inventory/production.ini playbooks/site.yml -vvv

# -v — подробно, -vv — очень подробно, -vvv — максимально подробно (показывает SSH-команды, JSON-ответы).
```

6. Запрос пароля для sudo:
```bash
ansible-playbook -i inventory/production.ini playbooks/site.yml --ask-become-pass
# Спросит пароль sudo. Полезно, если не настроен беспарольный sudo.
```
  
7. Запрос пароля для SSH:
```bash
ansible-playbook -i inventory/production.ini playbooks/site.yml --ask-pass

# Спросит пароль SSH. Нужно, если не настроены SSH-ключи.
```
  

##### Вспомогательные команды

1. Просмотр инвентаря (какие хосты видит Ansible):
```bash
ansible-inventory -i inventory/production.ini --list
ansible-inventory -i inventory/production.ini --graph
# --graph — покажет дерево групп и хостов. Очень удобно для отладки инвентаря.
```
  
2. Просмотр доступных модулей:
```bash
ansible-doc -l
ansible-doc ping
ansible-doc apt

# -l — список всех модулей.
# ansible-doc <модуль> — документация по конкретному модулю.
```
  
3. Шифрование секретов (Ansible Vault):
```bash
ansible-vault create secrets.yml
ansible-vault edit secrets.yml
ansible-vault encrypt secrets.yml
ansible-vault decrypt secrets.yml
ansible-vault view secrets.yml

# Используется для хранения паролей и ключей в зашифрованном виде.
# Запуск плейбука с vault: ansible-playbook site.yml --ask-vault-pass
```
  
4. Проверка версии:
```bash
ansible --version
```

##### Шпаргалка по флагам

| Флаг                       | Что делает                                  |
| -------------------------- | ------------------------------------------- |
| `-i`                       | Указать инвентарь                           |
| `-m`                       | Указать модуль (для ad-hoc)                 |
| `-a`                       | Аргументы модуля                            |
| `-b` / `--become`          | Выполнить от root (sudo)                    |
| `-K` / `--ask-become-pass` | Спросить пароль sudo                        |
| `-k` / `--ask-pass`        | Спросить пароль SSH                         |
| `-u`                       | Указать пользователя SSH                    |
| `-l` / `--limit`           | Ограничить хосты                            |
| `-t` / `--tags`            | Запустить только задачи с тегами            |
| `--check`                  | Режим проверки (dry-run)                    |
| `-v` / `-vv` / `-vvv`      | Уровень подробности вывода                  |
| `--list-hosts`             | Показать, на каких хостах будет выполняться |


##### Команды списком

```bash
# Запуск плейбука с использованием инвентаря по умолчанию (обычно /etc/ansible/hosts)
ansible-playbook playbook.yml

# Запуск плейбука с указанием конкретного файла инвентаря в формате INI
ansible-playbook -i inventory.ini playbook.yml

# Запуск плейбука с использованием файла "hosts" в качестве инвентаря
ansible-playbook -i hosts playbook.yml

# Запуск плейбука только для одного хоста "webserver1" из инвентаря
ansible-playbook -i inventory.ini playbook.yml --limit webserver1

# Запуск плейбука в режиме проверки (dry-run) без фактического внесения изменений
ansible-playbook playbook.yml --check

# Запуск плейбука с подробным выводом (уровень детализации - один "v")
ansible-playbook playbook.yml -v

# Запуск плейбука с запросом пароля для подключения по SSH (ask-pass)
ansible-playbook playbook.yml -k

# Запуск плейбука с запросом пароля sudo для повышения привилегий (ask-become-pass)
ansible-playbook playbook.yml -K

# Запуск плейбука с запросом обоих паролей: для SSH и для sudo
ansible-playbook playbook.yml -k -K

# Запуск плейбука с запросом пароля для расшифровки зашифрованных файлов Ansible Vault
ansible-playbook playbook.yml --ask-vault-pass

# Запуск плейбука с использованием файла, содержащего пароль для расшифровки Ansible Vault
ansible-playbook playbook.yml --vault-password-file ~/.vault_pass.txt
```
